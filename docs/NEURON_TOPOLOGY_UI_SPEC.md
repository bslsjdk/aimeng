 # AIMENG 神经元网络视图与 Android UI 修复规范

## 架构表达：不要画成 Transformer

AIMENG 的神经元管理视图应表达可独立训练、评估、组合和替换的神经元集合，而不是默认采用 Transformer 的固定层级图。

禁止把以下内容作为默认架构暗示：
- 规则排列的 Encoder/Decoder 层堆叠；
- Multi-Head Attention / Q-K-V 路径；
- 未经运行轨迹证实的全连接线；
- 仅为视觉效果绘制的虚构连接、活跃度或能力评分。

推荐使用可缩放的“神经元关系图”：
- 每个节点来自真实 registry / checkpoint，展示稳定 ID、启用状态、能力标签、独立测试分数和最后活动时间。
- 只有存在真实连接记录、协同实验或任务轨迹证据时才绘制边；边记录来源、权重/强度、样本数、最近验证时间。
- 节点位置可用力导向/聚类布局辅助阅读，但布局位置不得暗示固定神经网络层。
- 颜色和形状要有明确图例：候选、优秀、隔离/淘汰、禁用、未评估。不能仅靠颜色区分。
- 支持按任务、能力、状态过滤；点击节点打开独立详情；边可查看其证据。空注册表显示空状态和导入操作，不得用演示节点冒充真实数据。
- 网络图仅是观察工具。它不能单独证明语言理解、推理能力或整体模型质量。

## 训练、筛选和连接闭环

1. 从实际训练/checkpoint 创建有来源信息的 neuron artifact。
2. 使用隔离的 held-out 测试集测量能力、错误率、成本和稳定性。
3. 在重复测试及多任务结果上比较候选，保留优秀版本；边的新增/增强必须有协同实验或轨迹证据。
4. 低分节点先停用并进入可恢复的隔离区，经过复测后再决定归档；任何物理删除都必须由用户显式确认。
5. 所有变更写入 JSONL 事件日志，关联 run ID、神经元 ID、版本、数据集指纹、评测指标和决定理由。

## Android 窗口安全区要求

修复实际 Android 页面时：
- 使用 WindowInsetsCompat 处理状态栏、刘海/挖孔和导航栏 inset；内容区域不得延伸到系统导航栏下方。
- 主要页面根布局正确应用顶部与底部系统栏 inset，底部按钮容器额外留出导航栏安全区。
- 使用滚动容器或约束布局，确保小屏、横屏、字体放大时底部操作可滚动到达。
- 顶部标题/工具栏避开状态栏与刘海，避免重复叠加 padding/inset。
- 不要通过固定写死 24dp/48dp 来假定所有设备系统栏高度。
- 不要通过隐藏系统导航栏来“修复”按钮遮挡。
- 在 Android 15/16 edge-to-edge 情况下检查 WindowCompat.setDecorFitsSystemWindows 与 inset 分配，确保 inset 只应用一次，避免内容被推得过低或仍被遮挡。

## 验收

- 真实空注册表不会显示任何假神经元。
- 节点/边可追溯到真实记录；无证据的连接不显示。
- 顶部标题完整可见，系统状态栏不遮字。
- 所有底部操作按钮位于系统导航栏安全区上方，可点击且可滚动到达。
- 三键导航与手势导航均测试；小屏与大字体均测试。
- UI 相关异常、点击操作、布局尺寸与运行时错误可导出诊断日志。
- 在真实目标 APK/源码上编译、安装和实机验证后才能标记 UI 修复完成。
