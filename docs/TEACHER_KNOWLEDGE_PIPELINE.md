# Ornith 1.5 9B 知识进入 AIMENG 的路径

## 知识不是一个可以直接复制出来的文件

9B GGUF 里的能力主要编码在模型参数中。我们不能把这些参数直接复制到轻量路由器里，也不能把 Q4_K_M GGUF 当作普通反向传播训练检查点。初始阶段采用“冻结教师 + 可追溯知识库 + 已验证任务轨迹”，以后再评估学生模型蒸馏。

## 三条不同的知识通道

### A. 可检索的显式知识库（最先做）

让 9B 教师针对明确主题生成结构化记录。每条记录保留稳定 ID、主题标签、知识正文、适用范围、教师模型标识与模型文件 SHA-256、生成提示版本、来源/引用、验证方式与状态、数据拆分及许可/隐私审查状态。

导入时做 schema 校验、规范化、内容哈希去重。只有通过外部来源核验、程序测试或人工审核的条目才能标为 verified。未验证内容可隔离保存，不能当作事实真值。

这条通道让控制器/小模型通过检索调用知识，不代表知识已被压进它的神经权重。第一版先用 JSONL 作为便携格式；规模扩大后再接入向量索引。

### B. 任务轨迹与程序性经验

收集真实任务、计划、工具调用、失败类别、独立验证结果、最终修复。代码任务以测试/构建为优先验证器；事实任务保存可追溯来源；开放式回答没有可靠判定时标为 unknown。把“怎么完成任务”与“世界事实是什么”分开存储。

### C. 参数蒸馏/训练（后续阶段）

1. 用教师生成候选问答、解释、工具轨迹或偏好对；
2. 过滤重复、错误、无来源事实、提示泄漏和测试集污染；
3. 人工/程序验证后拆分 train/validation/test；
4. 训练与目标学生模型架构兼容的可训练检查点；
5. 独立评测知识准确率、任务成功率、遗忘、延迟与峰值内存；
6. 通过门槛后发布学生模型；失败则保留原版本。

路由器首先学习“何时调用什么资源/策略”，不是靠它自身存储 9B 的全部知识。真正的参数蒸馏需要学生模型、训练算力和独立评测，不能从一个 GGUF 文件自动变出来。

## 初始数据格式

每行一个 JSON 对象，结构如下。此为格式示意，不是真实知识条目：

{
  "schema_version": "aimeng.knowledge.v1",
  "record_id": "sha256:...",
  "topic": "python.exceptions",
  "content": "Python 中异常处理的核心规则……",
  "scope": ["python", "runtime"],
  "teacher": {
    "model": "Ornith-1.5-9B-Q4_K_M",
    "model_sha256": "填入真实模型文件哈希",
    "prompt_version": "knowledge-extract-v1"
  },
  "provenance": [],
  "verification": {
    "status": "pending",
    "method": "manual_or_external_source",
    "verifier_version": null
  },
  "split": "unassigned"
}

## 质量规则

- 不把教师自信程度或自我评价当作独立验证。
- 不把教师生成的虚构引用当作来源。
- 保存原始来源和模型版本，允许重新生成/撤销记录。
- 不导入私人对话、凭据或未经授权的数据。
- 检索结果带来源和验证状态；冲突时展示来源差异，而非静默覆盖。
- 事实库、程序性经验、任务临时工作记忆分开存储。
- GGUF 的哈希、张量清单和模型许可单独记录。

## 第一阶段验收

- [ ] 建立结构化知识记录格式与导入验证脚本。
- [ ] 重复内容可确定性去重。
- [ ] 未验证记录不能被升级为已验证。
- [ ] 9B 原模型文件不进入 Git。
- [ ] 知识库构建与参数训练分开记录。
- [ ] 后续蒸馏使用独立测试集，报告知识质量与资源开销。
