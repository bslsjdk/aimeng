# 训练优先路线图：先让 AI 学会，再做手机运行软件

## 决策

当前开发顺序明确为 **AIMENG 训练与能力验证优先，AI Android 运行时适配后置**。不为了未确定的训练产物，提前锁定部署格式或修改 `bslsjdk/ai`。

- `bslsjdk/aimeng`：训练准备、数据、教师知识提取、任务轨迹、学习算法、模型评测和训练产物。
- `bslsjdk/ai`：将来负责把通过验收的模型放进手机运行；当前阶段不需要为了配合训练而大改它。
- 模型格式：训练与数据管线保持格式无关。到部署阶段再按真实后端、速度、内存、算子支持和模型架构选择导出格式。

## 先说清楚“训练 AI”指什么

仓库现有实验能训练轻量预算控制器、学习策略选择并整理已验证经验；这些都**不是**已经训练出一个具备通用语言能力的新 9B 模型。

应把训练拆成不同目标并分别验收：

1. **任务行为学习**：从独立验证的真实任务轨迹中学习何时拆解、检查、调用工具、重试或停止。
2. **知识获取**：从教师和可靠来源构建带来源的知识库与高质量监督数据。
3. **学生模型训练/蒸馏**：当我们确定要把能力写入神经网络参数时，选择可训练的学生架构/检查点，用训练数据做 SFT/蒸馏并独立评测。
4. **部署优化**：模型能力过关后才确定手机推理格式、量化、导出和运行时集成。

前两项可以先做，并为后续真正的参数训练积累数据。不得把知识库、策略记忆或预算控制器称作已经学会了教师模型的全部知识。

## 阶段 0：基线和训练资源盘点

- [ ] 列出仓库现有脚本、数据、模型工件、测试和已知限制。
- [ ] 确认训练环境（Kaggle/Colab/本地）、可用 GPU、RAM、磁盘和每周时间预算。
- [ ] 为每个实验固定数据快照哈希、配置、随机种子、代码提交和日志。
- [ ] 不下载或提交巨型模型文件到 Git；模型工件通过受控缓存/外部存储管理。
- [ ] 先跑现有单元测试，区分代码通过、数据有效和真实训练成功三种状态。

**产物：** 可复现的实验清单与基线报告。没有资源盘点之前，不猜测能否完成 9B 全参数训练。

## 阶段 1：构建高质量训练数据

- [ ] 统一任务 JSONL schema：任务、上下文、目标输出/轨迹、工具结果、验证器、来源、许可、拆分。
- [ ] 以教师输出作为候选数据，不将教师自评当作事实验证。
- [ ] 对代码使用测试/编译；对封闭答案使用确定性验证；对事实知识保存可靠来源；无法可靠验证的样本标为 unknown。
- [ ] 按原始任务/来源分组切分 train/validation/test，避免同一任务的近重复版本泄漏到测试集。
- [ ] 规范化、去重、检查隐私与许可，保存每次数据版本的 manifest 和哈希。
- [ ] 先制作小而高质量的代表性数据集，跑通全流程，再扩规模。

**产物：** 版本化的教师候选集、验证集、测试集与数据质量报告。

## 阶段 2：先训练可量化的小目标

先训练能清楚评估的行为策略/预算控制器，比较规则基线与学习策略。每个样本必须来自真实运行与可信验证。用独立 test 集报告任务通过率、错误类型、平均延迟、迭代次数与可用内存指标。

这阶段的意义是验证数据管线和学习闭环，而不是把它误认为最终通用 AI。只有当控制器在未见任务上稳定优于基线，才接受为有效训练产物。

## 阶段 3：学生模型/参数蒸馏（单独立项）

先选一个真实可训练的学生检查点与目标架构，再决定训练框架和格式。可能需要教师生成的监督问答、解释、工具轨迹或偏好数据；通过质量筛选后做 SFT/蒸馏。量化推理工件不能自动当作完整训练检查点。

每次训练都必须：
- 保存基线 checkpoint，不覆盖唯一原件；
- 记录数据哈希、配置、训练日志和随机种子；
- 使用独立 validation 选择 checkpoint，使用未参与调参的 test 做最终评估；
- 检查遗忘、幻觉、工具遵循、任务成功率、模型体积和推理资源；
- 训练失败或退化时保留旧版本，不能用“loss 降了”代替能力验证。

## 阶段 4：冻结模型能力门槛后再做手机部署

只有在目标模型通过能力评测后，才比较运行格式和后端。部署决策以真实 Android 上的整应用峰值 PSS、首 token 延迟、生成速度、输出质量和崩溃率为依据。4 GiB 是硬限制，必须留安全余量；训练机指标不能替代手机测量。

届时才修改 `bslsjdk/ai`，增加必要的工件加载/导出适配和推理接口。训练数据与评测格式保持可移植，不需要因为更换部署格式而重做数据。

## 第一批可执行工作

1. 审计现有 AIMENG 脚本与测试，修正文档里把 GGUF 当成固定目标的表述，但保留旧实验作为历史基线。
2. 定义统一的任务轨迹和知识记录格式、校验、去重、拆分与 manifest。
3. 准备教师知识抽取模板，并以少量主题试产候选数据。
4. 对候选数据做独立验证，构建第一份小型训练/验证/测试切分。
5. 跑通现有行为控制器训练与独立评估，形成真实基线。
6. 根据真实训练资源和目标能力，决定是否启动学生模型 SFT/蒸馏。

## 不可伪造的验收规则

- “脚本存在”不等于“训练跑过”。
- “训练 loss 下降”不等于“能力提高”。
- “教师生成了内容”不等于“内容正确”。
- “预算控制器能预测”不等于“主模型权重已经训练”。
- “模型文件较小”不等于“手机峰值内存低于 4096 MiB”。
- 没有真实日志、独立测试和可复现配置，不发布成功结论。
