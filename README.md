# Aimeng：GGUF 基础模型的动态神经元调度训练

本仓库用于训练轻量级神经元组调度器与评估内存/质量权衡。基础模型作为冻结教师/基线，不在第一阶段直接改写 GGUF 权重。

## 目标

- 以指定的 9B Q4 GGUF 作为冻结基线，先验证文件、架构、量化类型与推理能力。
- 训练小型路由器，预测哪些结构化 FFN 通道组值得尝试，以及何时扩大候选池。
- 以任务质量为硬门槛，再优化真实延迟、计算量和峰值 RSS/PSS。
- 导出小型路由策略和版本化 manifest，供独立 Android 运行仓库集成。
- 最终整个 Android 软件运行时不超过 4 GiB；训练机内存不等于手机运行时内存。

## 重要边界

GGUF 是推理/量化格式，不等同于可直接进行标准梯度训练的原始训练权重。第一阶段将 GGUF 用作冻结基线与质量参照。要训练神经元组实际跳过计算的能力，还需要可控执行后端支持结构化通道掩码/分块计算，并验证量化张量布局、输出质量和真实速度。不能只训练一个分类器就宣称模型内存会变小。

GGUF 文件不会提交到 Git 仓库：9B 模型通常是数 GB，Git 普通文件与仓库克隆都不适合存放它。将模型放在训练机器的本地数据盘或受控模型存储中，通过环境变量 AIMENG_MODEL_GGUF 指向文件。模型来源、文件名和 SHA-256 写入本地 manifest；不要把模型二进制塞进源码提交。

## 第一阶段：可复现基线

1. 安装 Python 3.10+。
2. 安装依赖：python -m pip install -r requirements.txt。
3. 设置模型路径：
   - Linux/macOS：export AIMENG_MODEL_GGUF=/path/to/your-9b-q4.gguf
   - Windows PowerShell：$env:AIMENG_MODEL_GGUF="D:\\models\\your-9b-q4.gguf"
4. 检查模型文件：python scripts/inspect_gguf.py --output runs/gguf_manifest.json
5. 保存基线任务集、模型输出、token/s、首 token 延迟、峰值内存和失败记录。模型输出质量必须有可复现的评测集。

## 训练路线

- Stage A：冻结 GGUF，记录质量、耗时、峰值内存与后端信息。
- Stage B：在支持 hook/掩码的研究执行器中，对候选 FFN 通道组进行消融/组合实验；不能用普通 GGUF logits 冒充内部激活。
- Stage C：先监督学习候选组排序与扩容判断，再考虑 PPO/其他强化学习。路由器规模保持很小。
- Stage D：候选池质量不足时逐级扩容；到达预算上限仍失败时回退完整路径，而不是输出假成功。
- Stage E：证明后端真的减少了权重读取/矩阵运算，且真机峰值内存与任务质量达标。
- Stage F：导出路由器、分组索引、校准版本、适用模型 SHA 与资源配置；运行时仓库独立集成。

## 4 GiB 运行时硬约束

运行时预算由 Android 侧统一控制。训练仓库使用同一目标约束来评估，但不把训练进程内存误算成手机进程内存。测量至少记录进程峰值 RSS/PSS、映射权重、KV cache、后端/NPU 缓冲区（可获得时）、上下文长度、并发数和设备/驱动版本。保留安全余量；不能将文件大小或 mmap 虚拟地址空间当作峰值 RAM。
