# 训练实施计划与验收门槛

## 阶段 0：锁定模型身份

- 明确 9B GGUF 的准确文件名、来源、架构、量化类型和 SHA-256。
- 检查 GGUF metadata、tensor names/shapes/types。
- 禁止从“9B Q4”猜测模型架构；同为 9B 的模型不保证层结构、FFN 形状或 tokenizer 相同。
- GGUF 仅作为冻结推理基线；不要把它伪装成可直接用 AdamW 更新的训练权重。

## 阶段 1：建立完整路径基线

固定评测集、提示词模板、采样参数和后端版本。记录：
- 可自动验证的任务成功率/正确率；
- 首 token 延迟、生成 token/s、总耗时；
- 峰值 RSS/PSS（设备可提供时）；
- KV cache 配置、上下文长度、线程数、NPU/GPU/CPU 后端；
- 崩溃、OOM、超时和不支持的算子。

同一设备至少重复运行多次，报告中位数与高分位数，不用单次最好成绩。

## 阶段 2：生成结构化通道组实验数据

优先研究 FFN 中间通道，先以 128 通道为初始分组候选，并通过真实模型结构校验是否适合。分组大小不是硬编码的模型事实。

每条样本至少包含：
- 模型 SHA、层号、分组配置、任务 ID；
- 候选掩码/路由动作；
- 与完整模型输出的差异；
- 任务客观评分；
- 实际执行时间、实际计算量（若后端可测）和峰值内存；
- 是否触发扩容、扩容后是否恢复质量。

关键要求：实验执行器必须真正跳过相应通道计算，或明确标记为“仅消融模拟”。仅对输出打分不能证明节省了推理资源。

## 阶段 3：训练小型路由器

初始动作定义为每层的结构化组选择及候选池扩容档位。第一版先使用监督学习预测：
1. 候选组的预期贡献/优先级；
2. 当前候选池是否应扩容；
3. 在质量门槛已满足时，是否可以停止扩容。

奖励目标采用分层约束：
- 第一层：任务质量达到门槛，否则该策略不可接受；
- 第二层：在合格策略中优化真实延迟和计算成本；
- 第三层：在质量与速度满足要求时降低峰值内存。
- 对不必要扩容施加小惩罚；对成功恢复任务的必要扩容给予奖励。
- 不将模型自身未经校准的“自信程度”当作正确性标签。

有了可靠数据后才尝试 PPO 等强化学习方法；保留固定随机种子、训练/验证/测试拆分与可恢复 checkpoint。

## 阶段 4：动态扩容与安全回退

候选池档位从小到大尝试。若客观质量检查失败、路由器不确定或出现分布外输入，则扩大候选池；到达最大预算仍无法满足门槛时，回退完整执行路径或明确返回失败。不得静默宣称成功。

## 阶段 5：证明内存和速度收益

必须分别报告：
- GGUF 文件大小；
- 进程峰值 RSS/PSS；
- NPU/后端缓冲区与共享内存（若可测）；
- 延迟、token/s、任务质量；
- 运行时是否真的跳过矩阵运算和权重读取。

mmap 本身不保证降低峰值 RAM；结构化稀疏也不保证在硬件上更快。所有结论以目标后端和目标手机的测量为准。

## 阶段 6：手机端集成

训练仓库只输出版本化路由器、分组索引和校准 manifest。Android 仓库独立实现路由执行、内存预算控制、回退和遥测。整款应用的运行时峰值必须低于 4096 MiB，并预留安全余量。
