# AIMENG ↔ AI 运行时集成契约

## 项目边界

- `bslsjdk/ai`：实际 Android 本地 AI 运行软件，负责模型加载、tokenizer、推理执行、上下文/KV、QNN HTP V73 路径、性能与内存遥测。
- `bslsjdk/aimeng`：训练与实验侧，负责数据集、任务轨迹、策略/路由器训练、独立评测、知识库构建和策略版本产物。
- 两个仓库不是同一个项目。训练侧不得假设运行时只能接受 GGUF，也不得自行发明一个与运行时不兼容的模型封装。

## 模型格式原则

**由运行时和目标硬件决定模型工件格式，而不是反过来。**

当前 `bslsjdk/ai/docs/PROJECT_MEMORY.md` 指定的首选模型为 `Ornith-1.5-9B-MLX-4bit`，使用 Safetensors / affine 4-bit quantization；GGUF/llama.cpp 是旧基线或兼容路径，不是 AIMENG 必须锁死的唯一格式。

因此：
- 运行时教师的真实模型 ID、权重格式、tokenizer、量化参数和 SHA-256 必须从 ai 项目的当前配置/构建产物读取或明确记录。
- 训练数据、经验 JSONL、评测结果采用与模型工件无关的可移植 schema。
- 路由器/策略模型的输出格式由 ai 运行时实际接口决定；不兼容时增加明确的转换/导出步骤，不在两个仓库各写一套互不相认的格式。
- 若将来更换为其他手机推理后端或格式，知识记录和评测轨迹不需要重做，只需更换工件适配器。

## 训练产物与运行产物必须区分

1. **知识库/任务经验**：JSONL 等显式数据，运行时可检索；它不是模型权重。
2. **策略/路由器**：小型决策模型或确定性策略，选择预算、知识来源或可用计算路径；必须通过运行时接口消费。
3. **学生模型检查点**：真正训练得到的权重，必须有对应架构、tokenizer、量化/导出步骤和独立评测。
4. **部署工件**：最终被 Android runtime 读取的格式。可以与训练检查点不同，但转换过程必须可重复并验证输出一致性。

不能把“保存了教师回答”描述成“学生模型已经学会”，也不能把“路由器训练完成”描述成“9B 权重已经训练”。

## 必须协商的运行时接口

下一步从 ai 仓库实际代码中确认并版本化：
- 模型/工件加载与卸载入口；
- tokenize、prefill、decode/generate 入口；
- 可用预算参数（context、KV cache、tile/batch、线程、最大输出）；
- 任务状态和知识检索的输入方式；
- 性能遥测：TTFT、prefill、decode tok/s、实际读取权重字节；
- 整应用峰值 PSS、native RSS/HWM、QNN buffer 与 KV 状态；
- 运行时对策略模型/知识检索的调用接口；
- 错误、超时、OOM 的安全回退。

以上接口必须基于真实源码核对，不得因为文档写了某个字段就假设已实现。

## 4 GiB 门槛

整款 Android 应用峰值必须低于 4096 MiB 并留出安全余量。训练机显存、模型文件大小、虚拟映射大小和子进程单独 RSS 都不能替代目标手机整应用 PSS/峰值测量。任何训练出来的策略都不能覆盖内存硬限制。

## 当前状态

此契约是仓库间的设计约定。AIMENG 目前新增的固定容量工作集仍是元数据调度原型，不代表 ai runtime 已经接入动态权重分页。下一阶段要直接检查 `bslsjdk/ai` 的真实加载/推理/遥测代码，按现有接口设计 AIMENG 适配层，并通过可重复构建和真机测量验证。
