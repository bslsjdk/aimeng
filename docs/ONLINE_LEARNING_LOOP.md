# 在线学习闭环：推理产生证据，受控机制决定更新

## 目的与结论

借鉴生物学习中的局部可塑性、预测误差和经验巩固，但不把大脑机制当成已被完整证明的单一算法。工程目标是：一次任务既完成当前推理，也产生可验证的学习证据；系统可以在任务内调整执行策略，并在任务结束后决定哪些经验能进入持久控制器。

**关键区分：推理、记录、适应、持久学习是四件事。** 多轮推理本身不等于训练；只有更新了明确的状态或参数，才称为适应/学习。

## 双时间尺度架构

```text
任务开始
  -> 读取已验证控制器 + 当前设备资源状态
  -> 选择初始预算
  -> 推理一轮
  -> 独立验证器/工具结果提供误差信号
  -> 判断误差来源与资源安全
       ├─ 答案通过：停止，记录成功轨迹
       ├─ 质量不足且资源安全：调整预算/路由/提示策略，再推理
       ├─ 内存风险：先降低并发、上下文、批大小或输出上限
       └─ 反馈不可靠：标记 unknown，不更新质量目标
  -> 任务结束：冻结本次轨迹，执行经验结算
  -> 去重、验证、分组、检测异常与数据泄漏
  -> 离线训练候选控制器
  -> 独立测试 + 资源/质量门槛
  -> 通过才版本化发布，否则保留旧控制器
```

### 时间尺度 A：任务内适应（快速、可丢弃）

首版只允许修改**本次任务的临时状态和可控执行参数**，例如：

- 当前预算档位、最大输出 token、上下文上限、并发、线程等后端真实支持的参数；
- 已验证的工具选择、重试次数、候选策略排序；
- 任务工作区中的临时笔记、错误类别和候选计划。

这属于策略适应，不是主模型权重训练。任务内的变化默认不直接写入全局控制器，不让一次错误反馈污染所有后续任务。

### 时间尺度 B：任务后巩固（慢速、持久）

任务结束后才结算经验：

1. 把每轮输入特征、策略动作、验证结果、成本、回退原因组成轨迹；
2. 只对有独立证据的标签训练监督目标；开放式答案若无法可靠评分，标为 `unknown`；
3. 同一任务的不同预算必须配对，并按任务/来源拆分 train、validation、test；
4. 训练新的轻量控制器，与规则基线和旧版本比较；
5. 只有独立测试通过质量门槛，且延迟、峰值内存、失败率和回退率没有不可接受退化，才发布新版本；
6. 保留 checkpoint、数据快照哈希、配置、后端版本和基准结果，允许回滚。

## 每轮误差如何产生

误差信号必须来自可复核来源，而不是仅凭模型说“我错了”或“我很确定”。

| 任务类型 | 优先误差信号 | 不足时 |
|---|---|---|
| 代码 | 测试、编译、静态检查 | 标记 unknown 或要求人工检查 |
| 数学/封闭答案 | 精确结果或规范化比较 | 不确定时不伪造分数 |
| JSON/工具调用 | schema、参数与执行结果 | 记录具体约束失败 |
| 检索/事实问答 | 可追溯来源、事实核验 | 证据不足则 unknown |
| 开放式写作 | 独立人工评估或盲化成对比较 | 不把模型自评直接当真值 |

“误差”还要分类：知识错误、指令理解错误、格式错误、工具失败、预算不足、超时、内存风险。不同原因需要不同动作。增加 token 预算无法修复所有问题，给每个错误都加算力只是昂贵的迷信。

## 奖励与决策：先硬门槛，再优化成本

不建议把质量、轮数、PSS、延迟直接混成一个可以互相抵消的总分。否则足够快的错误答案可能因为省资源而得到高分。

采用分层决策：

1. **安全约束：** 整个 Android 应用运行时峰值 RAM 必须低于 4096 MiB；安全约束不可被奖励函数覆盖。
2. **质量门槛：** 未达到任务质量要求的策略不具备胜出资格。
3. **合格策略内优化：** 比较端到端延迟、实际计算成本、峰值 PSS、迭代次数、失败率和回退率。
4. **避免无效迭代：** 若验证结果没有改善、又没有合理的新证据，下一轮必须改变动作或停止，不能原样重复。
5. **资源成本必须实测：** 未验证的通道掩码、路由变化或“跳过比例”不算计算节省。

可以用下式作为分析指标，而不是越过硬门槛的唯一奖励：

```
合格策略成本 =
  a * 归一化端到端延迟
+ b * 归一化峰值 PSS
+ c * 额外迭代次数
+ d * 回退/失败代价
```

只有通过质量与安全门槛的策略才比较这个成本。系数应由实际应用目标和测量数据确定，不提前编造固定权重。

## 是否在推理时更新权重？

### 方案 1：在线更新路由/预算（首选）

推理主模型冻结。根据每轮验证结果更新本任务的执行计划；跨任务的持久控制器通过已验证轨迹离线训练。这是第一阶段可落地方案。

### 方案 2：任务内临时适配器（后续实验）

可研究 LoRA、轻量适配器或临时记忆，但要单独证明训练成本、收益和遗忘风险。默认不把临时更新合并进基础模型；任务结束后可丢弃。不能把量化 GGUF 当成可以直接常规反向传播的完整训练检查点。

### 方案 3：持续在线更新全局权重（暂不启用）

风险包括错误标签污染、灾难性遗忘、奖励投机、数据泄漏、更新与评测互相污染，以及运行时内存/延迟失控。没有可靠验证器、回滚机制和独立评测前，不应在手机上直接更新全局模型权重。

## 重要的科学边界

- 大脑确实具有在线可塑性，但并非每次思考都会形成持久突触变化。
- 预测编码/误差驱动更新是有影响力的理论框架，并非已证明能统一解释所有脑区与认知活动的完整算法。
- 计算机也可以在线学习；是否采用在线更新取决于反馈质量、计算成本、稳定性与遗忘风险，不是简单由“计算快或慢”决定。
- 工程实现应借鉴“预测—反馈—局部调整—经验巩固”的抽象循环，而不是声称复刻了人脑。

## 第一阶段验收

- [ ] 每轮都有唯一 run/iteration ID，并记录所选动作和实际生效参数；
- [ ] 每轮质量由任务适配的独立验证器给出 pass/fail/unknown；
- [ ] unknown 不作为正负奖励标签；
- [ ] 质量失败时只在资源安全条件下扩容；
- [ ] Android 运行时硬限制 4096 MiB 不可被控制器覆盖；
- [ ] 任务内适应与跨任务持久学习分离；
- [ ] 新控制器在独立任务集上对比旧策略，未通过则不发布；
- [ ] 报告真实测量；不把代码实现、模拟跳算或单次成功写成已验证收益。
